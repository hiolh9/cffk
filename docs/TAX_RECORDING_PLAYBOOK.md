# SparkPay 税务记录操作手册（系统内怎么记，不是怎么向 LHDN 申报）

> 本文只说明：**在本系统里如何登记、勾选、汇总、归档与对账**，方便报税时有据可查。  
> **不构成税务或法律意见**；是否应税、税率、申报表填写请以 LHDN / 持牌税务顾问为准。

---

## 1. 系统里和「税」相关的几块

| 模块 | 路径 / 位置 | 记什么 |
|------|-------------|--------|
| 税务中心 | 后台 → **税务中心**（`/accounting/tax`） | 税种、未报义务、申报批次、到期与估算税额 |
| 商品编辑 | 后台 → 商品 → **涉及税种** | 该商品是否纳入某税种义务 |
| 订单支付成功 | 自动 | 按商品税种生成 `tax_obligation`（未报义务） |
| 日记账与 P&L | 后台 → **日记账与 P&L** | 实际付给税局的钱（`Expense`） |
| 月度导出 | 日记账与 P&L → 一键导出 | 销售 / 结算 / GL 等 CSV，作底稿 |

**不要混淆：**

- **税务义务 / 批次** =「哪些单要进哪一期申报」的管理记录  
- **日记账 Expense** =「已经付给税局多少钱」的现金账  
- **P&L 净利润** = 经营损益，不是申报表本身  

三者配合，才是完整记录。

## 2. 首次设置（只需做一次或偶尔调整）

### 2.1 税种（税务中心）

1. 打开 **税务中心**。  
2. 确认已有税种（如 SQL 种子的 `SST`、`WHT`），或点 **新建/编辑税种**。  
3. 建议填写：

| 字段 | 含义（记录用） |
|------|----------------|
| 代码 | 如 `SST`、`WHT`，唯一、稳定，勿频繁改 |
| 名称 | 显示名 |
| 默认税率 % | 估算税额用；申报前可在批次上再改 |
| 期后到期天数 | 用于「建议到期日」= 最久未报义务日 + 该天数 |
| 提醒天数 | 如 `14,7,3,1`，距到期这些天数时看板标「需提醒」 |

4. 不用的税种可停用（`isActive = false`），避免商品误勾。

### 2.2 商品挂税种（关键）

1. 打开 **商品编辑**。  
2. 在 **涉及税种** 中勾选适用税种（可多选；可不选）。  
3. 保存。系统写入 `product_tax`。  

**规则：**

- **勾了** → 该商品订单支付成功后，会生成对应税种的 **Open 义务**。  
- **不勾** → 不产生义务，报税汇总时不会自动进该税种批次。  
- 同一商品可同时挂 SST 与其它自定义税种（若业务需要）。  
- **WHT** 若税种计算基础为 `MANUAL`，可能不会按销售额自动生成义务，需在税务中心 **手工建批次** 记录（见第 5 节）。

### 2.3 改税种或税率后

- 改 **默认 %**：只影响 **之后新产生** 的义务（已存在 Open 行仍用生成时的税率，除非重建批次时传入新 %）。  
- 改商品勾选：只影响 **之后新订单**；历史义务不会自动删改。

## 3. 日常：订单成交时系统自动记什么

当订单 **支付成功**（`confirmOrderPayment` → PAID）且商品已挂税种时，系统会：

1. 按 `product_tax` 为每个税种插一条 **`tax_obligation`**。  
2. 状态 = **`Open`**（未纳入已申报批次）。  
3. 记录：订单号、商品、交易时间、收入基数（MYR）、税率、估算税额。  

**你需要做的日常动作：**

- 保证售卖中的应税商品已正确勾税种。  
- 无需每单手工记账。  
- 若测试单、内部单不应进申报：该商品不要勾税种，或事后在义务上标记 Waived（若后台已提供；否则不要划进申报批次）。

**自检 SQL（可选）：**

```sql
SELECT id, orderId, taxTypeId, revenueMyr, ratePercent, taxAmountMyr, status
FROM tax_obligation
ORDER BY id DESC
LIMIT 20;
```

## 4. 按期汇总：生成申报批次（报税前在系统里做的记录）

目标：把某一期间内、某税种下所有 **Open** 义务收成一包，对应你要申报的那一期。

### 4.1 操作步骤

1. 打开 **税务中心**，看该税种：  
   - 未报笔数  
   - 最久未报（天）  
   - 建议到期日  
   - 未报税基 / 估算税额  
2. 点 **生成本月批次**（或按界面选择 `YYYY-MM`）。  
3. 确认或修改 **税率 %**（用于本批重算税额）。  
4. 提交 → 生成 **Draft** 批次：  
   - 义务变为 **`Included`**  
   - 写入 `tax_return_batch` + `tax_return_batch_order`  
5. 用批次里的 **税基、税额、订单列表** 去填官方申报（系统外）。  
6. 申报提交后，在系统点 **标记已申报（Filed）**。  
   - 义务 → **`Filed`**  
   - 批次状态 → **`Filed`**  
7. 可选：在批次备注里写 **回执号 / 申报参考号**（`receiptRef`）。

### 4.2 批次状态含义（记录口径）

| 状态 | 含义 |
|------|------|
| `Draft` | 已汇总，尚未当作「已向税局申报」 |
| `Ready` | 可选用：资料已齐、待提交官方 |
| `Filed` | 已在官方完成申报（系统记录） |
| `Paid` | 税款已缴纳（若流程支持；否则用日记账表示付款） |

### 4.3 「这单税记完了没有？」

- 该订单相关 `tax_obligation` 全部为 **`Filed`**（或 `Waived`）→ 已纳入已申报批次。  
- 仍为 **`Open`** → 还没进任何已 Filed 批次。  
- 无义务行 → 商品当时未挂该税种，或支付钩子未跑到（需查订单是否 PAID）。

## 5. 付款给税局：日记账怎么记

税务中心批次解决的是 **「哪些单、哪一期、多少估算税」**。  
**实际从银行扣款交给税局** 仍记在 **日记账与 P&L**：

| 项目 | 填写 |
|------|------|
| Type | `Expense` |
| Amount_MYR | **负数**（流出），如 `-600.00` |
| 可税前扣除 | 按顾问意见勾选（常见为是） |
| 描述 | 必须可检索，建议固定格式 |

**描述推荐格式（英文或马来文便于审计）：**

```text
SST payment period 2026-09 to 2026-10 ref <回执号>
WHT payment <payee/period> ref <回执号>
```

这样以后用关键词 `SST payment` / 期间能搜到「税是否已付」。

可选：在批次上关联 `glEntryId`（若界面支持），把「申报批次」和「付款分录」连起来。

**注意：**

- 日记账这笔是 **付款**，不要代替「标记 Filed」。  
- 不要把客户订单的 Gross 收入改成「净额」来假装已扣税；收入仍按销售全额规则记账，税单独走义务与费用。

## 6. 建议的月度 / 双月记录流程（清单）

适用于「先在系统记清楚，再去报税」：

1. **对销售**  
   - 月度导出或账本 CSV，确认 Success 订单齐全。  
2. **对义务**  
   - 税务中心：各税种 Open 笔数是否合理；异常单是否误挂税种。  
3. **建批次**  
   - 按申报期（如自然月或双月）生成 Draft，核对税基与估算税额。  
4. **导出底稿**  
   - 保存批次相关订单列表（或从 D1/导出 CSV），与申报期命名一致，例如：  
     `Sparkpay-SST-2026-09-10-obligations.csv`  
5. **官方申报**（系统外）  
6. **回写系统**  
   - 批次 **Filed** + 回执号  
   - 付款后日记账 **Expense** 负数 + 同期间描述  
7. **归档**（建议保留 ≥7 年）  
   - 批次说明 / 回执 PDF  
   - 销售与义务 CSV  
   - 银行扣款凭证  
   - 对应 GL 描述可搜索

## 7. SST 与 WHT 在记录上的区别（操作层面）

| | SST 类（销售额相关） | WHT 类（扣缴相关） |
|--|----------------------|---------------------|
| 商品勾选 | 应税商品勾选 | 通常不按「每个客户订单」自动挂 |
| 自动义务 | 支付成功 → Open 义务 | 若 `MANUAL`，可能无自动义务 |
| 批次 | 按销售期间从 Open 汇总 | 多按「付款对象 / 期间」手工建批次并填税基、税率 |
| 日记账 | 缴 SST 时 Expense | 缴 WHT 时 Expense，描述写明对象与期间 |

具体是否对某类数字商品征 SST、是否对供应商付款扣 WHT，**不在本手册范围内**，只要求：一旦你决定要记，就走「税种 →（商品）→ 义务/批次 → Filed → 付款 GL → 归档」。

## 8. 金额与正负号（记账约定）

| 位置 | 约定 |
|------|------|
| `tax_obligation.taxAmountMyr` / 批次税额 | **正数** = 估算或应付税额 |
| 日记账 `Expense` 付税 | **负数** = 现金流出 |
| 销售收入 | 仍按账本规则记 Gross，不在订单上「扣掉税再当收入」 |

批次上的税额用于 **申报底稿与估算**；最终以你向税局申报并缴付的金额为准，差异可在备注或下期调整说明中写清。

---

## 9. 禁止事项（避免记录失真）

1. 不申报却把批次标成 **Filed**（记录假完成）。  
2. 已 Filed 后私自改历史义务金额而不留痕迹。  
3. 把 **业主提款** 记成税。  
4. 把 **供应商预存款** 记成 SST/WHT。  
5. 应税商品不挂税种，导致义务为 0，却以为「系统说不用报」。  
6. 只记 GL 付款，从不建批次、不留订单清单（审计时无法说明税基来源）。

## 10. 速查表

| 你想记录的事 | 在哪操作 |
|--------------|----------|
| 新增一种税 / 改默认税率与提醒 | 税务中心 → 税种 |
| 某商品要不要进某税 | 商品编辑 → 涉及税种 → 保存 |
| 单笔销售自动应税义务 | 支付成功自动（需已挂税种） |
| 本期有哪些单未报、最久多久 | 税务中心看板 |
| 汇总本期并锁定清单 | 生成申报批次 |
| 标记「已向税局申报」 | 批次 → 标记已申报 |
| 标记「税已从银行付掉」 | 日记账 Expense 负数 + 清晰描述 |
| 整月底稿打包 | 月度一键导出 + 批次相关 CSV + 回执 |

## 11. 文件命名建议（归档）

```text
Sparkpay-TaxType-YYYY-MM-batch-id.txt          # 批次摘要
Sparkpay-TaxType-YYYY-MM-orders.csv            # 纳入申报的订单
Sparkpay-TaxType-YYYY-MM-filing-receipt.pdf    # 官方回执
Sparkpay-TaxType-YYYY-MM-bank-payment.pdf      # 银行付款证明
```

与 `ACCOUNTING_PLAYBOOK` 中的月度 `Sparkpay-YYYY-MM-*.csv` 放同一归档目录，按年分文件夹。

---

**一句话：**  
商品勾税种 → 成交自动记 Open 义务 → 按期生成批次并 Filed → 付款记 Expense → 回执与 CSV 归档。  
这样报税时问的是「记录全不全」，而不是在系统里找「怎么填官方表格」。
